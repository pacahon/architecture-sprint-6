В приложении нет задач очень требовательным к вычислительным ресурсам, рост кол-ва пользователей имеет смысл масштабировать с помощью HPA.

С учетом высоких требований к доступности сервиса (RTO — 45 мин., RPO — 15 мин., доступность 99.9%) будем использовать Active-Active фэйловер-стратегию.

Ввиду того, что требуется обслуживать пользователей из разных регионов и для них нужно обеспечить одинаковое время загрузки страниц, ноды k8s будут расположены в разных зонах доступности - для этого заведём мультикластерный k8s, каждый кластер будет находиться в своей зоне доступности, запрос пользователя по умолчанию будет попадать на ближайший ДЦ и не будет его покидать, уменьшая сетевые задержки. 

В случае недоступности зоны GLSB перенаправит трафик на доступную зону, тем самым оперативнее реагируя на недоступность зоны и положительно сказываясь на RT в случае возврата доступности кластера. HPA в зоне доступности поднимет новые инстансы приложения, если текущих мощностей кластера не будет хватать для покрытия возросшей нагрузки.

Для обеспечения доступности БД организуем отказоустойчивый кластер postgresql на основе Patroni. В каждой зоне доступности будет свой мастер, между зонами доступности настраиваем потоковую репликацию данных, бэкапы делаем с помощью pgBackRest (на схеме не отображено)
